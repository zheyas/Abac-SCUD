# СКУД — живая 3D-карта доступа

Веб-приложение для визуализации и администрирования системы контроля и управления доступом. На интерактивной 3D-карте отображаются здания, их режим работы и доступность для текущего пользователя с учётом роли, времени, дня недели и активности смены.

## Возможности

- интерактивная 3D-карта на Three.js;
- статусы объектов в реальном времени:
  - зелёный — проход разрешён;
  - жёлтый — здание закрыто по графику;
  - красный — доступ запрещён политикой;
- ABAC-политики для ролей и зданий;
- собственный режим работы каждого здания, включая 24/7 и ночные интервалы;
- динамическое солнце, луна, звёзды, освещение и тени;
- расчёт положения солнца по часовому поясу региона пользователя;
- ускорение, замедление, пауза и ручная перемотка времени суток;
- переключение рабочей смены пользователя;
- автоматическая активация и деактивация смен по расписанию;
- имитация входа в здание с визуальным разрешением или отказом;
- журнал фактических попыток прохода;
- персональные правила для конкретного пользователя поверх правил его роли;
- административная панель для управления зданиями, пользователями и политиками;
- автоматическое создание и безопасное обновление базы SQLite.

## Технологии

- Python 3.11+
- Flask 3
- SQLite
- bcrypt
- Three.js
- HTML, CSS и JavaScript без дополнительного frontend-сборщика

## Быстрый запуск

1. Создайте и активируйте виртуальное окружение:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

2. Установите зависимости:

   ```bash
   pip install Flask==3.1.3 bcrypt==5.0.0
   ```

3. Запустите приложение:

   ```bash
   python main.py
   ```

4. Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080).

При первом запуске приложение создаст `abac_scud.db`, таблицы, демонстрационные роли, пользователей, здания и политики. Повторный запуск не дублирует данные.

> Для загрузки Three.js при первом открытии страницы требуется подключение к интернету.

## Как рассчитывается доступ

Результат проверки формируется последовательно:

1. Проверяется режим работы здания.
2. Проверяется активность учётной записи.
3. Для объектов с общим доступом проход разрешается сразу.
4. Для остальных объектов ищется политика, соответствующая роли пользователя.
5. Проверяются персональные правила пользователя — при совпадении они имеют приоритет над ролевыми.
6. Учитываются день недели, временной интервал и требование активной смены.

Правило может иметь эффект **«разрешить»** или **«запретить»**. Если одновременно совпали несколько правил одного уровня, запрет имеет приоритет.

Поддерживаются интервалы, переходящие через полночь, например `20:00–06:00`.

### Формат дней недели

В графиках и политиках используются английские трёхбуквенные обозначения:

```text
Mon,Tue,Wed,Thu,Fri
```

Значение `All` означает все дни недели.

## Управление картой

- ЛКМ — вращение камеры;
- ПКМ — перемещение камеры;
- колесо мыши — масштаб;
- `−` и `+` — изменение скорости времени;
- центральная кнопка — пауза или продолжение;
- «Сейчас» — возврат к реальному времени;
- шкала суток — ручной выбор времени.

Администратор также может включить режим редактирования, выбрать здание и изменить его положение непосредственно на карте.

Чтобы имитировать проход, выберите здание в списке или на карте и нажмите **«Попытаться войти»**. Маркер пользователя приблизится ко входу, система покажет результат проверки, а событие попадёт в журнал.

## Рабочие смены

Для пользователя доступны два режима:

- **ручной** — пользователь самостоятельно начинает и завершает смену;
- **автоматический** — состояние смены вычисляется по дням и времени, заданным администратором.

Автосмена использует время симуляции. Поэтому при перемотке суток карта сразу пересчитывает состояние смены и доступы.

## Административная панель

В панели доступны три раздела:

- **Здания** — название, цвет, координаты, размеры, график и общий доступ;
- **Пользователи** — логин, роль, ручная или автоматическая смена и блокировка учётной записи;
- **Правила доступа** — разрешение или запрет для роли либо конкретного пользователя;
- **Журнал проходов** — успешные входы и отказы с причиной и применённым правилом.

Изменения применяются к карте и проверкам доступа без пересоздания базы.

## Основные API-маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/api/login` | авторизация |
| `POST` | `/api/logout` | выход |
| `GET` | `/api/buildings` | список зданий |
| `POST` | `/api/access_status` | статусы доступа для пользователя и времени |
| `POST` | `/api/toggle_shift` | переключение смены |
| `POST` | `/api/entry_attempt` | имитация и регистрация попытки входа |
| `GET` | `/api/access_events` | последние попытки текущего пользователя |
| `POST` | `/api/admin/buildings` | создание здания |
| `PUT/DELETE` | `/api/admin/buildings/<id>` | изменение или удаление здания |
| `POST` | `/api/admin/users` | создание пользователя |
| `PUT/DELETE` | `/api/admin/users/<id>` | изменение или удаление пользователя |
| `POST` | `/api/admin/policies` | создание политики |
| `PUT/DELETE` | `/api/admin/policies/<id>` | изменение или удаление политики |

Административные маршруты требуют активной сессии пользователя с ролью администратора.

## База данных

SQLite-база хранится в файле `abac_scud.db` и содержит таблицы:

- `roles`;
- `users`;
- `buildings`;
- `policies`;
- `access_events` — журнал разрешённых и отклонённых попыток входа;
- `app_meta` — версия выполненных миграций.

Файл базы исключён из Git через `.gitignore`.

## Важно

Проект использует встроенный сервер Flask и демонстрационный секрет сессии. Для публичного развёртывания необходимо:

- вынести секретный ключ в переменную окружения;
- отключить debug-режим;
- использовать production WSGI-сервер;
- включить HTTPS и защиту от CSRF;
- добавить аудит административных действий и более детальное разграничение полномочий.
